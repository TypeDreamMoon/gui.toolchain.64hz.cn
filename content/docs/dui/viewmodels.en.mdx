<Callout type="info">
  This page describes what is on `main` after 1.0.0, and ships with the next version (see the [Changelog](/en/docs/changelog)).
</Callout>

A view model is an object that holds a screen's state and commands, apart from the widgets that show them. The widgets
bind to it; it never refers to them. One view model can serve several screens, and its logic can be tested without any
UI.

```dui
class /Game/UI/WBP_Hud

viewmodels {
    PlayerVM    Player                   // the host gives it
    SettingsVM  Settings = new           // this widget makes one
    InventoryVM Inventory = global       // from the game's registry, by class
    InventoryVM Stash = global "Stash"   // by class and name
    PartyVM     Party = parent           // the nearest enclosing widget's PartyVM
}

VerticalBox Root {
    Text Name { Text <- Player.Name }
    Native.Slider Volume { Value <-> Settings.MasterVolume }
    Native.Button Apply { OnClicked += Settings.Apply() }
}
```

Any `UObject` class can be one. `UDreamViewModel` is the convenient base; anything implementing
`INotifyFieldValueChanged` — UE's own `UMVVMViewModelBase` included — is subscribed to the same way, and DreamGUI does
not depend on the ModelViewViewModel plugin.

## Declaring

`viewmodels { … }` goes at the top of the file, like `props` and `events`. Each line is a type and a name, and optionally
where the object comes from.

The type is a class: its reflected name (`PlayerVM` for a C++ `UPlayerVM`), a full path (`/Script/MyGame.PlayerVM`,
`/Game/UI/BP_PlayerVM`), or a name given by `use /Script/MyGame.PlayerVM as PlayerVM`.

Each entry becomes a variable of the class — an object reference of that class, FieldNotify, Expose on Spawn, in the
*ViewModels* category — so everything that can set a variable can hand the widget its view model.

| Code | When |
| --- | --- |
| [DUI2021](/en/docs/diagnostics/dui2xxx#dui2021) | a line that is not `Type Name` with an optional source, or the block inside a node |
| [DUI3024](/en/docs/diagnostics/dui3xxx#dui3024) | two entries of one name |
| [DUI6015](/en/docs/diagnostics/dui6xxx#dui6015) | a type that names no class, or two |
| [DUI6016](/en/docs/diagnostics/dui6xxx#dui6016) | a name another member of the class already answers to |
| [DUI6017](/en/docs/diagnostics/dui6xxx#dui6017) | `= new` of an abstract class |

When the parent is a C++ class that already has a property of that name, an object reference of this very class, the
line declares no second variable: it describes that property — where its object comes from.

## Where the object comes from

| Written | Means |
| --- | --- |
| `PlayerVM Player` | The host gives it: a pin of the node that creates the widget, `SetViewModel(Name, Object)` from C++ or Blueprint, a Blueprint Set of the variable, or a host's `.dui` line on this widget used as a component (`Row Audio { Channel <- Settings.Audio }`). |
| `= new` | The widget makes one, outered to itself, when it was given none. Also in the designer's preview, which then shows the view model's defaults; such an instance answers `IsDesignTimeInstance()` true. |
| `= global`, `= global "Name"` | From `UDreamViewModelSubsystem` (one per game instance), by class, and by name when one is written. When nothing fits yet, the entry waits and is filled when a fitting object is registered. Empty in the designer. |
| `= parent`, `= parent "Name"` | The nearest enclosing user widget's entry of a fitting class (and that name, when written), followed as it changes. What a component uses to share its host's view model without being handed it. |

The object is in place before On Initialized runs and before any binding's first value. An entry the host already set
keeps what it was given: `= new`, `= global` and `= parent` act only on an entry nobody filled.

### The host gives it

In a Blueprint, the **Create Dream Widget** node has a pin for every Expose on Spawn property, and every `viewmodels`
entry is one. The pins are assigned **before** the widget initializes, so On Initialized and every binding's first value
already see them (see [Widget Blueprints](/en/docs/concepts/widget-blueprints#showing-it)).

In C++, `SetViewModel` hands an object over by the entry's name. To do it before the widget initializes, create it in
two halves:

```cpp
#include "Core/DreamUserWidget.h"

UDreamUserWidget* Hud = BeginCreateDreamWidget(GetWorld(), HudClass);
Hud->SetViewModel(TEXT("Player"), PlayerVM);   // written into the entry's variable, the field broadcast
FinishCreateDreamWidget(Hud);                   // Initialize, register
Hud->AddToViewport();
```

`SetViewModel` works later too: the object is written into the variable and the field is broadcast, so every binding
reading through it re-reads. Null clears the entry. It returns false, with a warning in the log, when the class has no
such entry or the object is of another class. `GetViewModel(Name)` reads what an entry holds right now.

A component's entry can be bound by its host's `.dui`, as a prop can:

```dui
// The component: DUI/UI/Components/AudioRow.dui
class /Game/UI/Components/WBP_AudioRow

viewmodels {
    AudioChannelVM Channel
}

HorizontalBox Root {
    Text Label { Text <- Channel.DisplayName }
    Native.Slider Level { Value <-> Channel.Level }
}
```

```dui
// The host
class /Game/UI/WBP_Settings
use "UI/Components/AudioRow.dui" as AudioRow

viewmodels {
    SettingsVM Settings = new
}

VerticalBox Root {
    AudioRow Music { Channel <- Settings.Music }
    AudioRow Voice { Channel <- Settings.Voice }
}
```

### `= global`: the game's shared view models

`UDreamViewModelSubsystem` is a game instance subsystem: it outlives level loads and is not shared between PIE clients.
It holds what it is given strongly until it is unregistered or the game instance shuts down.

| Member | Does |
| --- | --- |
| `Register(ViewModel, Name = None)` | Shares an object. `None` registers it by its class alone. |
| `Unregister(ViewModel)` | Takes it out, under whatever name it was registered. |
| `Find(Class, Name = None)` | Looks it up by the rule below; null when nothing fits. The return pin takes the shape of `Class`. |
| `FindOrCreate(Class, Name = None)` | Finds, or makes one (outered to the game instance), registers it under `Name` and returns it. Null for an abstract class. |
| `OnRegistered` | Broadcast after every `Register` that changed the registry. |
| `UDreamViewModelSubsystem::Get(WorldContext)` | C++: the registry of the world's game instance. Null where there is none: the designer's preview, an editor world. |

The lookup: with a name, the entry of that name whose object is of the class; with none, the first entry registered with
no name whose object is of the class, else the first entry of any name whose object is. Registering an object a second
time under the same name replaces nothing; registering a second object under a name already taken replaces the first
and broadcasts, which is how a game swaps a global view model wholesale. With no name, an entry is keyed by the
object's exact class: objects of two classes sit side by side unnamed, and a second unnamed object of the same class
replaces the first.

A `= global` entry that finds nothing when the widget is made waits: an object that fits, registered later, fills it,
and the bindings through it update.

### `= parent`: the host's view model

`= parent` walks up the parent chain to the nearest user widget and takes its entry of a fitting class (and that name,
when written), following it as it changes. Initialize and Construct both look again; after moving a widget under
another host in C++, `RefreshParentViewModels()` does.

## Reading and writing

Bindings, routes and loops reach a view model through **member paths**:

| Written | See |
| --- | --- |
| `Text <- Player.Name`, `Text <- Player.Stats.Title`, `Text <- Player.FormatGold(Player.Gold)` | [Bindings](/en/docs/dui/bindings#--drives-a-property) |
| `Value <-> Settings.MasterVolume` | [Mirroring](/en/docs/dui/bindings#--mirrors-both-ways) |
| `OnClicked += Settings.Apply()`, `OnValueChanged += Settings.SetVolume(Value)` | [Routes](/en/docs/dui/bindings#---and--route-an-event) |
| `for Item in Inventory.Items`, `Event -> Item.Use()` | [for and each](/en/docs/dui/control-flow#for-and-each) |

While an object along a path is not set, the binding is not evaluated and the property keeps the value it had; a route
calls nothing.

## Writing a view model

### C++

```cpp
#include "ViewModel/DreamViewModel.h"

UCLASS()
class UPlayerVM : public UDreamViewModel
{
    GENERATED_BODY()
public:
    void SetHealth(float InHealth) { DREAM_VM_SET(Health, InHealth); }

    UFUNCTION(BlueprintCallable, Category = "Player")
    void Heal(float Amount) { SetHealth(Health + Amount); }

protected:
    UPROPERTY(BlueprintReadOnly, FieldNotify, Category = "Player")
    float Health = 100.f;
};
```

- Members a binding reads must be visible to Blueprint: `BlueprintReadOnly` / `BlueprintReadWrite` properties,
  `BlueprintCallable` / `BlueprintPure` functions ([DUI5023](/en/docs/diagnostics/dui5xxx#dui5023) names the one that is not).
- `DREAM_VM_SET(Member, Value)` assigns when the value changed and announces the field; when it did not, it returns false
  and announces nothing, so a setter called every frame with the same value costs a comparison. An `FText` compares by
  the string it displays. The macro works in any `INotifyFieldValueChanged` class with FieldNotify properties, not only
  `UDreamViewModel`'s.
- A value computed from others (`GoldText` from `Gold`) is announced with `BroadcastFieldValueChanged` when its sources
  change. Offering such display-ready members is how a view model converts values; there is no separate converter.
- A view model that wants to react when the UI writes a value back through `<->` offers `Set<Member>` (BlueprintCallable,
  one parameter): `<->` calls it instead of writing the property. A read-only property with no such setter is
  [DUI6020](/en/docs/diagnostics/dui6xxx#dui6020).

### Blueprint, UnrealSharp and UE's MVVM

- **Blueprint**: make a Blueprint whose parent is `DreamViewModel` and tick FieldNotify on its variables. A Set node of a
  FieldNotify variable announces on its own; a field computed from others is announced with the *Broadcast Field Value
  Changed* node. `UDreamViewModel` finds its world through its outer, so world-context nodes work in a Blueprint subclass.
- **UnrealSharp**: a `[FieldNotify]` property's setter announces on its own. For a path to read it, its `[UProperty]`
  says `BlueprintReadOnly` or `BlueprintReadWrite`.
- **`UMVVMViewModelBase`**: a view model already written for UE's MVVM works as it is, subscribed to the same way.

A class that does not implement `INotifyFieldValueChanged` works too; bindings through it are read every frame.

### Design-time instances

An instance the designer makes for a `= new` entry answers `IsDesignTimeInstance()` true: no game is running, and no
subsystem a game would set up exists. A view model that reaches into the game in its initialization checks it first.

## When a binding updates

The compiler records every variable and member a `<-` expression reads. When **each** of them is FieldNotify — the
variable on this class, and every member along a path on an object that implements `INotifyFieldValueChanged` — the
binding is subscribed: it updates when one of them announces a change, and costs nothing in between. Otherwise it is
read every frame. A call with arguments (`Format(Gold)`) may read anything, so a binding holding one is always read
every frame; a view model offering the formatted value as a member is the way out.

In a `for` or an `each`, a copy whose item announces a change of a member it shows is updated alone; the rest of the
list is not touched.

The console command `DreamUI.Binding.Dump` lists every live widget's bindings — how many are subscribed, how many read
every frame, and why; `DreamUI.Binding.ForcePoll 1` reads every binding of the widgets initialized after it every frame,
which tells a change nobody announced from a wrong binding. See [Debugging](/en/docs/tools/debugging#diagnostic-commands).

<Callout type="warn">
  C++ that assigns a FieldNotify member without broadcasting it — which FieldNotify never allowed — used to be covered
  up by the per-frame poll, and is not any more. Use `DREAM_VM_SET` or `BroadcastFieldValueChanged`, or find the member
  with `DreamUI.Binding.ForcePoll 1`.
</Callout>

## FieldNotify members of a C++ user widget

`UDreamUserWidget` implements `INotifyFieldValueChanged` itself, and a C++ subclass of it can declare
`UPROPERTY(FieldNotify)` members: like UMG's `Widget.h`, `DreamUserWidget.h` includes the header the code UHT generates
for them needs. A `.dui` binding to such a member subscribes through the class's descriptor, and `DREAM_VM_SET` is its
setter:

```cpp
UCLASS(Abstract)
class UMyListPage : public UDreamTextUserWidget
{
    GENERATED_BODY()
public:
    void SetHasSelection(bool bIn) { DREAM_VM_SET(bHasSelection, bIn); }

protected:
    UPROPERTY(BlueprintReadOnly, FieldNotify, Category = "List")
    bool bHasSelection = false;
};
```

```dui
Widget Details { Shown <- bHasSelection }
```
